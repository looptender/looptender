- New loops follow the standing wake policy of the running build. Setup records the `prompt.md` it writes (`prompt.md.wake-policy.json`); while the file is unchanged, each wake sends the running build's wording followed by the file's task, and the file is not rewritten. Any edit ends that, and the file is sent exactly as written. Loops set up earlier are not changed: `status`, `doctor` and the new `prompt-policy show` say which generated wording they match, or that they are hand-edited, and `prompt-policy apply` (owner only, not during a check) moves a loop to the current wording, keeping its task, its command path where it had one, and the previous file. A loop moved from an older wording starts receiving guidance that wording lacked: versions 1 to 3 gain the delegation paragraph ("At the start of substantial work … assign bounded work to child lanes now"), versions 1, 2 and 4 gain the coordinator paragraph, including "A newer owner instruction can reactivate previously parked work", and version 1 gains "After a phase finishes … take one concrete next action". Nothing a later wording says removes a hold or a permission requirement. See [standing wake policy](docs/setup.md#standing-wake-policy).
