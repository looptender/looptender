- A loop checked by ticks with no daemon (an external scheduler, a BB automation or ticks run by hand) is now described the same way everywhere: `status --json` sets `daemon.nextCheck` to the same sentence as `runtime.nextCheck` and the text, with new `daemon.checkedBy: "ticks"` and `daemon.cadence`; `client status --json` carries the same three fields, and `doctor --json` its `nextCheck`. The BB plugin card says the loop is checked by ticks about every interval instead of "running supervisor not confirmed", and the macOS menu replaces "External scheduler: not inspected" with the same. The `shared:` warning no longer calls a paused or awaiting-a-person loop supervising: it says the loop is enabled but held, which hold, and that it sends nothing until a person resumes it. Hints, usage lines and the panel now print `looptender <command>` instead of the old `keepgoing <command>` (installed service definitions are unchanged).
