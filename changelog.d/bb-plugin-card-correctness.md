- BB plugin card: a pause or stop asked for from a thread's card now guards the card against acting on the wrong loop: the server refuses it unless that thread is the loop's primary or current target (from the loop's own status; for a saved setup, the thread it was saved for or its move destination). The caller names the thread itself and may leave it out, so this is not access control. Pausing a loop whose target is another thread asks first and names the loop and the thread it supervises. A superseded loop no longer says a person resumes it: it says, as `status` does, that resume is refused, and names the successor when `status --json` carries one. An unmanaged loop's Pause no longer sends an undefined `managedId`. The setup form's goal note now says `--with-goal` needs v0.1.5 or later.
