- Loop ownership now follows a handoff the supervisor makes itself when the loop's owner is the conversation being left: a handoff to a BB thread created for it (`bb.new_thread`) and an automatic switch-back move ownership to the thread that takes over. A running daemon keeps supervising across such moves instead of exiting, and a check that still carries the earlier owner's `BB_THREAD_ID` still runs; that thread's control commands are refused with a message naming the handoff. A loop owned by another thread, or by no one, keeps its owner, and explicit claims (`enable --take-over`, `transfer apply`) end the run as before. The move is saved to `state.json` before `control.json`, so a crash between the two is completed by the next check past the holds; held loops change nothing, and an explicit claim made in between wins. The first prompt of a created thread says whether it will own the loop. History records the move as control operation `supervisor_handoff`.
