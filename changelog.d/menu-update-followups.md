- The macOS menu's update no longer tells you an update happened that did not: the new menu says "looptender menu updated to <build>" only after the menu it replaced has really exited, and says nothing if that one keeps running. When the old menu stops the new one because it got busy, it confirms the new menu exited (a polite stop, then a forced one, then a message if it still runs) so two menus never remain. A chosen update whose installed build changed while it was being checked says so instead of doing nothing. The update logic (check, relaunch, the settle step and the aborts) moved into one class with a fake environment, and is tested without the app. Every CLI call the menu makes is bounded (25 to 120 seconds, then killed), so a hung call releases its work token and cannot keep the menu busy forever.
