- A daemon that switched to the installed build in place keeps the process's start: `startedAt` in the daemon's answer and `status --json` is when the process started, not the switch, with the new `buildStartedAt` for when the running build took over, and the earlier build's last pass is carried over, so the "computer probably slept" reading of an overdue loop still sees the same daemon. The switched process's command line now names the loop's configuration (`__adopt-build --handover-fd N -c CONFIG`) when the build switched to says in its probe answer that it accepts it; a build from before this is handed `--handover-fd N` alone, the only form it accepts, in either direction.
