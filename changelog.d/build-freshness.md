- The panel and the macOS menu now say how fresh each supervisor's build is, in the same words (one function in Go words them, and `panel list --json` and the dock report carry them): an up-to-date supervisor shows just its version; one that switched builds within the last 24 hours shows `Updated 2 h ago` with `Installed <date time> · was <old> · now <new>`; one that follows installs but has not switched shows `Update pending · switches at next check`; one that will not follow installs shows `Different build from the installed one`, or `Older build · restart the supervisor to update` only when both are plain releases and the installed one is newer, and `Not switching to the installed build` with the recorded reason when its switch was refused. What a person does is true for how it runs: under a service its own restart (`launchctl kickstart -k …` or `systemctl --user restart …`), never an exit the unit would not restart from; otherwise `looptender daemon-shutdown -c CONFIG` only for a daemon built after that command existed, with the words that the loop has no supervisor until it is started again, and `looptender daemon -c CONFIG`, never `start`, for a held or disabled loop. The summary says `N not on it`. A panel started before the latest install says so instead of counting. The Overview and the menu start with one line, `Build X installed <when> · N supervisors on it · M not on it`. Nothing restarts, resumes or re-enables a supervisor. `buildFreshness` (not `runtime.freshness`, which is the age of the last check) is an additive field on each dock loop, on the dock report, in `panel list --json` (per loop and once), and on `status --json` and `client status --json`, with `running`, `installed`, `was`, `now` and `switchedAt` fields; older menu and plugin builds ignore it, and a loop whose daemon reports no build says nothing.
- A refused switch is told by its cause: a restart is offered only where the installed build takes over only from one; a build older than the loop's state format points at the documented stop, restore and start; a build that would not start or validate gets no restart; and a temporary wait (low disk, a change at the last moment, another state directory) reads `Update pending · waiting`. A service's own restart is offered only while the loop is held and only when the supervisor is that service's process, and `panel list` and `client status` carry placeholders for the user ID and service label. A panel that is an earlier build than the installed file is detected by comparing digests, not file times.
