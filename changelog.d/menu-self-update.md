- The macOS menu now notices when the installed build differs from the one it is running (the link it was started through now leads elsewhere, the file at its path was replaced, or `<root>/current` beside its `builds/<id>` moved) and says so: a dot beside the icon, the item `Update available: relaunch to use <build>`, and one notification, `looptender menu: update available (<build>)`, for each installed build; clicking the notification relaunches. A new setting, `Update the menu automatically` (on by default), relaunches the menu by itself while it is closed and no change is being made, after checking that the new bundle exists, is runnable, matches this app and passes `codesign --verify`; it tries once for each installed build, keeps the old menu running and says why if it fails, and then says `looptender menu updated to <build>` once. The relaunch passes the same arguments and never changes Open at Login. Everything is local; nothing is fetched.
