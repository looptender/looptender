- An observed sessionpipe target can opt in to waking its session when it is idle (`sessionpipe.send: wake_only`, with a `loop.prompt`). Only the ordinary idle wake is sent, as an allow-list: notice wakes (child errors, usage warnings, an overloaded computer, assignments) and nudges, re-prompts, stops, handoffs and switch-backs stay held. Send limits, idle spacing and every hold apply, and nothing is sent while the session waits on a person or this computer's login session is unavailable. The wake runs `sessionpipe ask <harness>:<id> --quiet --text -` detached, with an allow-listed environment. The answer goes to the null device unread, and stderr is capped at 4 KiB in memory. A refusal within 3 s counts as not sent and keeps only its code. One wake is outstanding at a time, matched by process ID and start time. `status` and doctor show a wake still running and for how long. Builds from before this change refuse a configuration with `sessionpipe.send`. Off by default; fixture-tested with a stand-in sessionpipe.
