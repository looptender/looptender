- Fixes from a read-only sweep of an installed build. `validate` by a caller that does not own the loop (or whose state directory is not writable) now checks the configuration and says what is refused for it, instead of refusing before reading the file and advising a take-over; `context` says when the caller is not the owner (`callerStatus`). A paused loop's child-error record no longer says "The loop is not held"; a limit wait whose reset falls after the loop's own deadline says so, and `doctor` mentions a wait recorded on a held loop as information. A prompt's command prefix that runs another program file, or one that does not exist, is flagged by `status`, `doctor` and `prompt-policy show`, and `prompt-policy apply --refresh-prefix` previews rewriting it to the running program's path (`--yes` writes it). `bb looptender status` says how many registered loops it does not show and how to add one, and shortens long notes. Smaller: `doctor` no longer warns about a disabled loop's stale check or build label, or about a caller that only reads; a held loop's no-progress flag is marked as recorded before the hold; deadlines print in UTC; `--version` works; dev build labels with a suffix shorten like the others; `doctor` names the default connectivity target.
