- A daemon started from a loop's own BB thread now adopts an installed build after a handoff the supervisor made. The candidate's `validate` ran with that thread's `BB_THREAD_ID`, and once ownership had followed the handoff to the created thread, every installed build was refused as "does not validate this loop's configuration". The daemon's own ownership check (its lease, which follows such moves) is unchanged. `resume` run from a thread that lost ownership to such a handoff now says so, as the other control commands already did, instead of the generic different-thread refusal. Both were found by new end-to-end scenarios that run the incident with handoff ownership, child moves, the long limit wait, the wake policy and build adoption together (`TestScenarioIncident*`).
