# v0.3.0 — looptender, Account Router, Antigravity, Telegram, Sessionpipe, and Accounts & Panel Refresh

This release prepares **looptender v0.3.0** and **BB plugin v0.4.0** (distributed from the same tag). It collects everything merged since v0.2.0, including all work previously drafted under the unreleased v0.2.1 preparation notes (v0.2.1 was never tagged or published and is folded into this release). The entry-by-entry record is in [CHANGELOG.md](../../CHANGELOG.md), and packaging and candidate evidence is recorded in [release verification](../release-verification.md).

**Why 0.3.0 and not 0.2.1.** In a 0.x version the minor number marks significant capability additions and format changes:
- the CLI, repository module, default loop configuration filename (`looptender.yaml`), environment variable prefix (`LOOPTENDER_*`), and user interface are branded **looptender** (with compatibility shims for `keepgoing`, `KEEPGOING_*`, and `keepgoing.yaml`);
- the release adds the Antigravity ACP adapter, the local Account Router daemon, the Telegram remote channel, Sessionpipe observation/idle waking, the Accounts catalog and route editor in the panel, and loop archiving;
- several records advance in schema (`incidents.json` schema 14, run `graph.json` schema 3, `accounts.json` schema 2, headless wrapper protocol 3), so loops upgraded to v0.3.0 need the steps under [going back to v0.2.0](#going-back-to-v020) before running v0.2.0 again.

## What is new

**Naming and compatibility.**
- Command name `looptender` alongside `keepgoing`, `looptender.yaml` alongside `keepgoing.yaml`, `LOOPTENDER_*` environment variables (honoring legacy `KEEPGOING_*` when unset and refusing conflicting values), and migrated per-user panel/storage naming with bounded recovery hints.

**Account Router (local HTTP proxy for pooled subscriptions).**
- Local read-only credential reader (`internal/router/login`) for Claude Code (Linux private files / macOS Keychain) and Codex (`auth.json` + top-level `config.toml` store check), with strict file permissions, zero token/secret logging, and zero automatic login or credential copying.
- Pooled HTTP router proxy (`looptender router start|stop|status|service`) routing Anthropic and Codex/OpenAI requests across configured accounts with profile selection, process tracking, active pointer checks, and `doctor` diagnostics.
- Read-only **Account Router** summary card on the Panel Overview showing answering status, enabled/pointed counts, and service state.

**Antigravity ACP primary loops and `/usage` quota.**
- Standalone primary-only `adapter: antigravity` (`agy acp --stdio`) in configuration, schema, `doctor`, and `looptender init --agent antigravity`, using a detached ACP worker with create-once prompt reservations, exact `session/resume`, owned `stop --immediately`, per-message streaming bounds, process-group/job termination, 64 KiB stderr capture, turn-directory pruning, and fail-safe `unknown` classification on unstructured limit errors.
- `looptender session clear-unconfirmed` for operator recovery after an interrupted Antigravity turn start.
- Model-free `/usage` quota reads in `looptender accounts usage`, the Accounts panel, and the macOS menu for selected inherited `agy` accounts (`source: "agy:/usage"`, `freshness: "provider_unknown"`). Fallbacks, switch-back, explicit account directories, per-loop model flags, and IDE-chat attachment stay unavailable for Antigravity.

**Telegram remote channel (`TG1`–`TG4`).**
- Outbound HTTPS stdlib client (`internal/telegram`) with redirect refusal, 1 MiB response cap, token-redacted errors, `loop.report.format: telegram`, and `looptender telegram setup|status|test|poll|topics|disconnect` (plus `telegram service install|status|uninstall` on macOS/Linux and `doctor --telegram` diagnostics).
- Single-owner `?start=pair_<nonce>` private pairing locked to `allowed_user_id` and `allowed_chat_id` in atomic `0600` storage, redacted plain-text alerts, atomic confirmation state, per-loop forum topics with clean DM fallback on HTTP 400 (and no fallback on non-400 or transport errors), `/status`, `Pause`, `Stop`, and two-step ticketed `Resume` buttons. Opt-in interactive `chat` steering (`TG5`) remains planned.

**Sessionpipe observation, idle waking, and pool diagnostics.**
- Tier-0 outbound reporting (`loop.report.format: sessionpipe`), read-only session observation (`adapter: sessionpipe`, `init --agent sessionpipe` deterministic naming), and opt-in idle-only waking (`sessionpipe.send: wake_only` via `sessionpipe ask`).
- Surfaced explicitly across the web panel, macOS menu, and BB plugin (`Observed, never woken` / `Observed, woken only when idle`, `Pause checking…` / `Resume checking…`, `sessionpipeWake` status, omitting Stop).
- Hardened wake persistence and `os.Lstat` symlink checks on `sessionpipe pool`, with `doctor` flagging stopped pool listeners, exhausted accounts, and clock-skewed resets.

**Web panel, Accounts, Routes, Usage, Archive, and notifications.**
- **Reviewed controls by default:** `looptender panel` now enables reviewed **Pause**, **Stop**, and **Resume** by default; `--read-only` disables all controls; `--allow-changes` adds route editing, account connect/remove/quota/selection-review/check actions, send-allowance editing, and in-place binary replacement, strictly bound to the starting caller and never allowing a supervised session to clear its own hold.
- **Accounts & Routes views:** Account catalog management (`accounts add|update|check|usage|connect|disconnect|remove`), explicit removal from the panel under `--allow-changes`, person-started **Connect Claude** / **Connect Codex** OAuth flows, separate Codex/Claude/Antigravity subscription quota caches, read-only local login file hints, bounded `--allow-changes` login status checks on Accounts load (`api/v1/account-checks`), eliminated duplicate "Not checked" plan labels, plain-word `context_changed` selection review recovery, and the guided **Routes** editor (`routes add|check|move|follow-standard`, expired-limit handling, and **Routes with unknown accounts** separation).
- **Archive & 3-day folding:** `looptender archive|unarchive`, panel/menu Archive controls without deleting runtime directories, and automatic 72-hour inactive loop folding in the sidebar/menu.
- **Usage, Versions & Notices:** 7-day **Usage** view summarizing withheld wakes and context-window history; **Versions** view and `daemon-shutdown` / in-place build adoption; shared panel/menu notification preferences with masked hold notes (`Show identifiers`), hidden-tab quietness, request timeouts, and Slack/Discord/ntfy/Pushover webhook presets.

**macOS menu, BB plugin, and supervision reliability.**
- **macOS menu preview:** Narrowed grouped Brand B layout, shared notification heartbeat lock, build self-update check, sessionpipe status, compact quota summaries, and Archive controls (`integrations/macos`, built separately from CLI archives).
- **Supervision, limits & recovery:** Quota switch threshold (`switch_at`), `looptender session reset`, `looptender wait --until ...` & `await-user --withdraw`, `loop.prompt_context`, Run Discovery D2 (`--routine` and registered pre-run graph distinction), headless connection-loss recovery scenarios (`TestScenarioHeadlessOutage*`) and wrapper protocol 3 completion, low-disk/full-disk safeguards and atomic private writes, damaged-control restrictive pause freeze, `--loop NAME` across `fallbacks`/`routes`, coordinator assignment lifecycle & whole-objective completion review (`complete --review-file`), opt-in PR backlog safeguard, and `transfer inventory` / explicit BB cross-provider transfer.

## Behaviour changes on upgrade

- **Controls on `looptender panel`:** Starting `looptender panel` without flags now allows reviewed loop **Pause**, **Stop**, and **Resume** (requiring confirmation before acting). Pass `--read-only` for the previous read-only default.
- **Headless runner protocol 3:** Detached headless completion uses wrapper protocol 3 (previously 2). Stop active headless loops or wait for in-flight turns to exit before replacing the binary, then restart daemons/services.
- **In-place build adoption:** On macOS and Linux, running daemons whose executable path now points at a verified new build can adopt it on restart/shutdown (`daemon-shutdown`); replacing a file on disk still does not upgrade an already running process without adoption or restart.
- **Strict configuration keys:** Older builds (`v0.2.0`) reject loop configurations or route lists containing `account`, `sessionpipe`, `sessionpipe.send`, `prompt_context`, `switch_at`, `antigravity`, `telegram`, or `router` settings.
- **Accounts catalog schema 2 & panel/CLI naming:** Plan metadata promotes `accounts.json` and quota caches to schema 2 (one-way promotion). Legacy `keepgoing.yaml` and `KEEPGOING_*` names remain accepted alongside `looptender.yaml` and `LOOPTENDER_*`.

## Upgrading

1. **Copy each loop's state directory** (and `accounts.json` / `routes.yaml` if present) before replacing the binary so going back remains possible.
2. Replace the binary (via Homebrew or release archive), stop or drain active detached headless turns, and restart any running daemon or background user service.
3. Update `integrations/bb-plugin-keepgoing` to **v0.4.0** if you use the BB plugin, then restart BB so updated bundles load cleanly.

## Going back to v0.2.0

A loop or account catalog written by `v0.3.0` can hold schema versions and fields `v0.2.0` cannot read:
- **`incidents.json` (schema 14) and run `graph.json` (schema 3):** `v0.2.0` refuses newer schemas; restore the pre-upgrade state copy if downgrading.
- **`accounts.json` and quota caches (schema 2):** `v0.2.0` refuses schema-2 account/quota metadata; restore pre-upgrade copies or re-create entries under `v0.2.0`.
- **Configuration & controls:** Remove `v0.3.0`-only keys (`account`, `antigravity`, `sessionpipe`, `prompt_context`, `switch_at`, `telegram`, `routes`) before loading configurations with `v0.2.0`, and restore pre-upgrade `control.json` if `v0.3.0` wrote restrictive damaged-control or archive fields.

## What is fixture-tested and what is live

Following [capability and documentation review](../testing.md#capability-and-documentation-review), implementation and offline CI coverage remain separate from live acceptance:

**Observed live (partial scope only):**
- **Antigravity (`agy 1.5.13`, macOS arm64):** live `initialize`, model-free `/usage` quota retrieval, `init --agent antigravity`, `doctor`, two-turn `session/new` -> `session/resume`, owned `stop --immediately`, and manual recovery of two real permission holds followed by completion (`docs/antigravity.md`). Unattended permission recovery, chat-only questions, and Linux/Windows installs remain open.
- **Sessionpipe observation:** live observation of one headless Claude Code session on macOS (`docs/testing.md`); no live idle wake (`wake_only`) has been delivered to a real session.
- **Network outage (2026-11-14) & Cursor (`v0.2.0`):** carried forward from prior single-machine observations; unattended child recovery and headless outage recovery on real provider CLIs remain unverified.

**Fixture-tested only, not verified live:**
- **Account Router:** pooled HTTP proxy, `router service`, login readers, and Panel Router card are verified with offline fixtures and stand-ins; live multi-account failover through the router proxy has not been exercised.
- **Telegram remote channel (`TG1`–`TG4`):** verified with offline loopback HTTP stand-ins and QR fixtures only; live Telegram Bot API polling, phone scanning, and background service restarts remain open.
- **Panel Accounts & Routes:** reviewed route editor, `accounts connect|remove|check`, `context_changed` selection review, local file login hints, 3-day folding, and Archive controls are covered by Go `-race` suites and `jsdom` DOM checks (`dock_page_check.mjs`); real-browser live panel sessions across Safari/Firefox/Windows remain unverified.
- **Headless outage recovery (`TestScenarioHeadlessOutage*`), quota `switch_at`, Slack/Discord/ntfy/Pushover presets, `daemon-shutdown`/in-place adoption, damaged-control freeze replay, and BB plugin v0.4.0 flows (New-thread toggle, Add to Looptender modal, Continue-existing, registry attach, reboot-surviving service install):** covered by offline scenario, SDK, controller, and DOM suites only. Live multi-turn onboarding-to-completion walkthroughs, Linux/Intel macOS Homebrew installs, and real Git plugin installs from the tag remain open.

## BB plugin v0.4.0

BB plugin **v0.4.0** ships from the `v0.3.0` tag and is installed separately ([plugin README](../../integrations/bb-plugin-keepgoing/README.md#install)):
- **Add to Looptender** modal redesign: **Minimize**/**Done** flow, current provider/model and size display, **Continue existing** tab with predecessor slug derivation (`bb-work-2`), collapsed **Options** (goal/standard routes/takeover), keyboard/roving-`tabIndex` accessibility, and **Supervision started** state preserved on diagnostics refresh.
- Reboot-surviving `service install` on macOS/Linux when starting background supervision, plus **Start checks** for overdue unheld loops with no responding daemon.
- Single-line ellipsis composer chips (supervised, `Covered by …` child-thread chips, checking, and add chips) preventing two-line wrapping or overlap.
- Weekly usage limit / quota "Why" reasons, `observed` / `observed (idle wakes)` sessionpipe visibility, build freshness lines, archive/display-name handling (`archiveLapsed`), CLI registry attachment, and New-thread screen toggle (unverified in live BB).
