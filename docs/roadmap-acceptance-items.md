# Roadmap item traceability matrix

Snapshot: [`f35a0a94`](https://github.com/looptender/looptender/blob/f35a0a9424f37a7f7078f98387564511589eac03/docs/roadmap.md).
Companion: [acceptance audit, execution results and evaluation protocol](roadmap-acceptance-audit.md).

This exhaustive index contains **402 checkbox items** and **133 additional
list requirements, Done claims and explicit acceptance paragraphs** (535 rows).
Every source list item is retained, including priorities, exclusions and repeated
cross-references, so no planned family silently disappears. The row ID is the
baseline source line, not a new roadmap priority. The source link contains the
full criterion and its dated evidence; the behavior column is its leading
sentence, shortened only for table readability.

Implementation labels describe the roadmap claim, not a new certification.
“Recorded implemented” can be source-only or released; the pinned source says
which. “Partial” includes implemented subsets whose full acceptance remains open.
**Full-product verdicts remain Unverified unless a concrete failing subset is
named.** Narrower Pass or Fail results are recorded in the companion's priority
table/execution record; a scoped Pass never closes a larger journey. Thus even a checked implementation row does not imply a fresh test run,
installation or end-to-end acceptance. Known failures are named in that record.

The evidence-family column resolves to concrete executable suites and missing
native/live/person-dependent checks. It is a mapping to existing **subset**
evidence, not a claim that those files test an unimplemented item. A planned row
has no complete executable evidence; adjacent local prerequisites are not proof.
Per-row missing acceptance includes all clauses in the pinned criterion, not
only the abbreviated first sentence. No roadmap box is changed by this index.
